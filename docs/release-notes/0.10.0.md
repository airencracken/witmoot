# Witmoot 0.10.0

A hardening release. It fixes the defects found in an audit, binds forms to
your session, and moves the sandbox, service configuration, mail and proxy
handling onto comfylib, the library Witmoot now shares with Imvault.

## Before you upgrade

- **Back up the whole stopped data directory.** The database moves from schema
  13 to 14 (the owner activity log). Older Witmoot releases refuse a newer
  database, so going back means restoring that backup.
- **Mail settings are checked at startup.** With `WITMOOT_SMTP_HOST` set,
  Witmoot now needs `WITMOOT_SMTP_FROM`, or a `WITMOOT_BASE_URL` with a domain
  name (mail then comes from `no-reply@` that domain). An unknown
  `WITMOOT_SMTP_TLS` value, a malformed sender or an unusable relay host stops
  startup. Before, an unrecognised TLS mode quietly sent mail in plaintext.
- **Site and board names must fit on one line.** `WITMOOT_NAME`, the site name
  in Settings, and board names and categories refuse line breaks and control
  characters, since the site name becomes the subject of reset mail. Existing
  boards still display; fix any multi-line name before saving it again.
- **The sandbox flags `--write-dir` and `--read-file` are gone**, and
  `WITMOOT_SANDBOX_WRITE_DIR` and `WITMOOT_SANDBOX_READ_FILE` are no longer
  read. For a private certificate authority, set `SSL_CERT_FILE` in the service
  environment; it works inside the sandbox too.
- **Bubblewrap 0.8 or later** is needed if you use the sandbox: the server can
  no longer create user namespaces of its own (`--disable-userns`).
- Pages opened before the upgrade may say "This form has expired" once.
  Reloading fixes it.

## Security

- Form tokens are tied to your sign-in, so a cookie planted by another site or
  subdomain cannot submit forms as you. Every state-changing request is
  checked, not only POST, and uploads are checked before they are read.
- Removing a member's invite access revokes their open invitations, and
  invitations from members without that access no longer admit anyone.
- Sign-in limits are kept per IPv6 /64, survive address floods by evicting old
  records, and no longer count successful sign-ins.
- Reset tokens never appear in logs, and unsent mail is never logged.
- Mail subjects are encoded, carry a Message-ID, and refuse header injection.
- Transactions take the write lock when they begin.
- New key files are written atomically, so a crash can no longer leave a short
  key behind.

## Fixes

- A rejected mascot or favicon upload no longer blanks the settings form, so a
  following save cannot erase the house rules.
- Uploads get five minutes to arrive; other request bodies stay tightly bounded.
- Failed exports abort instead of producing a truncated zip, and exports leave
  out names of boards and conversations the member can no longer read.
- Avatars are capped at four megapixels, like branding images.
- `reset-link` and `admin` read `WITMOOT_BASE_URL`, `WITMOOT_NAME` and the mail
  settings from the service configuration, and admin only emails complete links.
- systemd `EnvironmentFile=` paths may contain spaces.
- OpenRC passes `WITMOOT_SOURCE_URL` to the server.
- The sandbox check no longer needs `/usr/bin/true`, and merged-`/usr` symlinks
  are kept inside the sandbox.
- Not-found pages name the missing board, member, invitation or group, and
  invitation expiry shows a single "UTC".
- The owner activity log links removed messages and records replaced titles and
  avatar removals.
- Repeated member and invitation controls have per-person accessible names.

## Packaging

- The server logs its version at startup, and release builds are stamped.
- Release checks confirm the published source archive matches the tagged source.

Validation includes the full race suite, real Bubblewrap boundary tests,
deliberate mutations of the community, integration and sandbox rules, browser
workflows with and without JavaScript, and the Linux package lifecycle gates.
