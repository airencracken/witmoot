# Witmoot 0.9.0

Optional Linux confinement with Bubblewrap. Existing services keep their current
startup behavior until you enable it.

- `witmoot sandbox` starts the server with a restricted filesystem, separate
  process namespace and private temporary storage. HTTP and outbound networking
  remain available.
- `witmoot sandbox --check` verifies the configured policy without starting the
  server or creating a database.
- OpenRC supports `WITMOOT_SANDBOX=true`; systemd setup is documented with
  the namespace override required by its hardened unit.
- The launcher forwards shutdown signals to the server. Invalid mounts, missing
  Bubblewrap, unavailable namespaces and setuid Bubblewrap fail explicitly.
- Application secrets remain in the server environment, never in Bubblewrap's
  command-line arguments. Unrelated environment variables are removed.

No database schema changes from 0.8.0. Back up your data using your usual
procedure before upgrading. Install a current, patched, non-setuid Bubblewrap
package and verify namespace support as the service account before enabling it.

Setup, custom paths, limitations and verification:
[Linux confinement](https://github.com/airencracken/witmoot/blob/v0.9.0/docs/sandbox.md).

Validation includes the full race suite, real namespace and native server
lifecycle tests, and deliberate sandbox policy mutations. Linux package gates
also exercise the installed systemd service with Bubblewrap enabled.
