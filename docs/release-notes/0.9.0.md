# Witmoot 0.9.0

Optional Linux confinement with Bubblewrap. Services start as before until you
turn it on.

- `witmoot sandbox` starts the server with a restricted filesystem, its own
  process namespace and private temporary storage. Networking still works.
- `witmoot sandbox --check` tests the policy without starting the server or
  creating a database.
- OpenRC supports `WITMOOT_SANDBOX=true`. The systemd guide shows the override
  the hardened unit needs.
- The launcher passes shutdown signals to the server. Bad mounts, missing or
  setuid Bubblewrap, and blocked namespaces stop startup with an error.
- Secrets stay in the server's environment, never in Bubblewrap's arguments.

No database changes from 0.8.0. Back up as usual before upgrading. Install a
current, non-setuid Bubblewrap and run the check as the service account before
turning it on. See
[Linux confinement](https://github.com/airencracken/witmoot/blob/v0.9.0/docs/sandbox.md).
