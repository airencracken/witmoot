# Witmoot 0.11.0

Members can leave, owners can keep a portable community archive, and shared
images cost fewer upstream requests.

## Before you upgrade

- Stop the old server and back up the entire data directory, including
  `imvault.key`. The database moves from schema 14 to 15. Startup also saves a
  private database-only snapshot beside the database before applying migrations;
  if that fails, the upgrade stops. Restoring an older binary requires the
  corresponding old database and encryption key.
- Ordinary CLI commands now refuse outdated schemas. Use `witmoot migrate`
  explicitly with the service stopped, or let server startup migrate it.
- An HTTPS base URL always enables secure cookies. Loopback deployments with no
  trusted proxy list warn at startup because all visitors would share the proxy's
  sign-in rate-limit budget. Set the exact proxy addresses; headers remain
  untrusted until then.
- ZIP exports need temporary disk space. Set `TMPDIR` if necessary.

## Changes

- **Delete your account** requires your password and typed username. Sign-ins,
  profile information, image connections, invitations and access grants are
  cleared. Your messages become anonymous placeholders and your conversation
  titles become "Conversation"; other people's replies remain. The last owner
  must arrange a successor first. Imvault originals are managed separately.
- Owners can download a **community archive** from Settings. It includes private
  and empty boards, conversations, authorship, and audience and access rules,
  without passwords, sessions, email addresses or image credentials. An importer
  is still future work.
- Member and community archives include available shared Imvault previews and
  their links. Missing previews are explicitly marked. Archives are prepared
  before successful download headers, one at a time.
- Board deletion explains that other members' messages are erased and offers
  the community export and archiving as ways to preserve them.
- Shared image ownership checks are cached for 15 seconds per credential.
  Responses stream rather than buffering whole images, with private 15-second
  browser caching. Local conversation access is still checked on every request.
- Conversation, invitation and activity timestamps use the reader's timezone
  when JavaScript is enabled; server-rendered UTC remains the fallback.
- Deployment examples use reserved example domains for the image server.

See [data portability](../data-portability.md) for export scope and deletion
limits, and [deployment](../deployment.md) for migrations and backups.
